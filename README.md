# Figma Mixer

Плагин Figma для подготовки наборов векторной графики и создания композиций. Реализованы создание и пополнение наборов, композиции и пользовательские палитры.

## Запуск

1. В Figma Desktop открыть редактируемый файл.
2. Plugins → Development → Import plugin from manifest… → выбрать `dist/manifest.json`.
3. Запустить Figma Mixer. Уже подключённый плагин достаточно перезапустить.

Главный экран содержит библиотеку, палитру (включая «Пусть AI выберет») и поле темы или метафоры. Запрос сразу создаёт варианты на холсте; параметры вывода, ручной выбор и управление библиотеками доступны дополнительно. Полный сценарий: [Создание композиции по описанию](docs/user-flow.md).

## Создание набора

- Выделить целые объекты в Figma и выбрать «Из выделения Figma», либо открыть «Создать набор» и загрузить несколько SVG.
- Один выделенный объект или SVG-файл становится одним элементом. Внутренние векторы не разделяются.
- Проверить миниатюры, исправить названия, исключить лишние карточки, указать название набора и сохранить.
- Для одного контейнера доступен явный переход к его непосредственным вложенным объектам. Нативный Component Set Figma сохраняется одним элементом с вариантами.
- Существующий набор пополняется через «Добавить элементы». Описания и свойства вариантов задаются позже в карточке элемента.
- Несколько карточек можно отметить и объединить как варианты одного элемента. Их геометрия сохраняется.

Наборы содержат независимые копии исходников на странице «Mixer · Библиотека». Метаданные записываются в документ Figma. Изменения исходной графики не синхронизируются автоматически. Экспорт набора в JSON и обратный импорт переносят графику и метаданные между документами.

## Композиции

Выбрать библиотеку и палитру → описать идею → «Создать композиции». AI за один запрос подбирает разные сочетания предметов и допустимые палитры; весь план проверяется перед отрисовкой. Точные названия через запятую фиксируют состав; с конкретной палитрой этот путь работает локально. Формат, количество и детализация находятся в «Параметрах вывода». За запуск создаётся 1–12 вариантов из 1–8 предметов каждый, отдельными фреймами рядом с существующими. Запрос остаётся на экране. Экспорт и ручная доработка выполняются на холсте Figma; ручной генератор также сохраняет экспорт SVG.

Раскладка анализирует выбранную версию каждого элемента в актуальной палитре: Figma временно экспортирует PNG для локального анализа прозрачности, цвета и детализации. В результате на холст попадают исходные редактируемые векторы. Изображения анализа не отправляются в AI или внешние сервисы.

Визуальный вес зависит от площади силуэта, контраста с фоном, насыщенности и детализации. У равнозначных фигур нет обязательного главного предмета; дизайнер может назначить акцент явно. Названия объектов на построение не влияют. Общий масштаб сохраняет относительные размеры всех выбранных элементов. Объекты не исключаются ради более простой раскладки.

Доступны «Сбалансированная», «Динамичная» и «Свободный центр». Начальные построения задаются относительно границ кадра: крупные предметы могут заходить за край, а поддерживающие располагаются рядом или в другой группе. Поиск оценивает видимость силуэтов и контрастных деталей, перекрытия с учётом прозрачных отверстий, расстояния между силуэтами, зрительный центр и свободную область. «Свободный центр» защищает центральную треть по ширине и высоте и распределяет предметы по краям, включая несколько противоположных групп. Динамичное построение допускает разветвлённую диагональную группу вместо обязательного ряда.

По умолчанию включено композиционное кадрирование: для крупных предметов частичный выход за край входит в целевую раскладку. Видимость каждого предмета оценивается отдельно от перекрытия. Режим «Сохранить силуэты целиком» удерживает рамки всех объектов внутри кадра и может потребовать уменьшения группы. Выбранный способ построения указан в названии каждого созданного фрейма.

Фоновую роль можно назначить любому числу выбранных объектов с подготовленной фоновой версией в панели «Слои». Роль не назначается автоматически по названию или порядку выбора. До ручной перестановки слои сортируются по нижней границе целого объекта. После перетаскивания используется заданный порядок: выше в группе означает поверх остальных, фоновые версии всегда остаются позади основных. Этот порядок учитывается при оценке перекрытий и сохраняется в созданном фрейме. Кнопка в дополнительных настройках упорядочивает выделенные композиции, сохраняя ручной порядок, если он задан, либо сортируя по текущим позициям объектов. Координаты, размеры и графика сохраняются. Можно выделить несколько фреймов или вложенный предмет композиции. Сохранённые композиции со старой единственной фоновой ролью продолжают читаться.

Цвет фона выбирается из трёх фоновых цветов активной палитры. Готовые и пользовательские схемы представлены образцами; редактор показывает пары «исходный → новый» и крупный предпросмотр композиции. Подробности и формат JSON: [Палитры](docs/palettes.md). Диагональная плоскость по умолчанию выключена. Версия графики, кадрирование и плоскость находятся в дополнительных настройках. L и S выбирают готовые авторские исходники, а не запускают автоматическое упрощение контуров: у части объектов различаются лишь небольшие детали. Например, у наушников 84/79 контуров в L/S, у книги 53/51, у телефона 155/96.

Раздел «Подобрать элементы по описанию» принимает названия элементов или смысловой запрос. Точное совпадение названий обрабатывается локально. Для свободного текста используется выбранное AI-подключение; модель выбирает только элементы текущего набора.

В «Настройках AI» доступны DeepSeek (`deepseek-flash`), OpenAI (начальный ID `gpt-4.1-mini`) и OpenAI-совместимый сервис с собственным базовым адресом. ID модели редактируется. Ключ вводится вручную и хранится только в памяти текущей сессии; загрузка файла удалена. Адрес, провайдер и модель сохраняются локально в Figma без ключа. Смена сервиса требует его ключа, смена модели в том же сервисе сохраняет текущий ключ. Подробности: [AI-подключение](docs/ai-connection.md). `key.txt` исключён из Git и сборки.

## Интерфейс

Интерфейс переработан с применением [Unslop Дамира Соколовского](https://github.com/heydamir/unslop), CC BY 4.0. Нейтральные поверхности, единые размеры контролов и отступы оставляют цвет самой графике. На основном экране видны выбранные элементы; полный набор открывается через «Изменить». Подбор по описанию находится в этом же редакторе выбора. Кадрирование, L/S и операции с готовой композицией собраны в «Параметрах».

Основные действия сопровождаются контурными SVG-иконками: импорт, экспорт, сохранение, поиск, вкладки, слои и построение композиции. Горизонтальный, квадратный и вертикальный форматы имеют отдельные пиктограммы. Иконки используют единые размеры и толщину линий, сохраняют текстовые подписи и скрыты от скринридеров как декоративные элементы. Дополнительных зависимостей для иконок нет.

Панель «Слои» содержит две группы: фон сверху, основные ниже. Каждый выбранный предмет показан один раз с миниатюрой. Перетаскивание строки меняет порядок внутри группы или переносит предмет в другую группу, в том числе пустую. Во время переноса видны копия строки и линия вставки; длинный список прокручивается у края. Сброс за пределами списка и Escape отменяют перенос. У предмета без фоновой версии перенос на фон недоступен.

Звезда у основного предмета назначает единственный главный акцент; повторное нажатие возвращает автовыбор. Перенос акцента на фон снимает звезду. Стрелки остаются быстрым способом сменить группу. Для клавиатуры: Tab до ручки переноса, пробел или Enter для захвата, стрелки вверх/вниз для позиции, влево/вправо для перехода между группами, пробел или Enter для подтверждения. Touch использует удержание. Отдельного списка названий для выбора акцента нет. Лимиты генерации и общий масштаб предметов не менялись.

В Figma через agent-desktop проверены включение и снятие звезды, перенос предмета в фон и обратно, изменение количества и создание композиции с выбранными ролями. Проверка типов, 29 тестов и сборка проходят. Итоговые скриншоты: `.cache/qa/unslop-main.png`, `.cache/qa/unslop-layers-panel.png`. Полный импорт, все дополнительные настройки и клавиатурная навигация в этом проходе отдельно не проверялись.

## Ограничения текущего этапа

- SVG должен быть автономным вектором, без встроенного растра и внешних ресурсов. Текст перед импортом SVG необходимо перевести в кривые.
- Для импортированных элементов сохраняются исходные цвета. Встроенные и пользовательские палитры перекрашивают предметы стартового набора. Привязка к стилям и переменным Figma не реализована.
- Разделение произвольного SVG-листа на отдельные предметы не выполняется автоматически.
- Анализ силуэта выполняется на сетке 24 × 24. Тонкие детали и малые просветы могут оцениваться приближённо. Значимость деталей определяется по локальному контрасту, без распознавания назначения предметов; это не понимание 3D-сцены. На сложных наборах может потребоваться ручная корректировка.

## Разработка

Node.js, TypeScript, React, esbuild, Vitest. После установки зависимостей:

```powershell
node scripts/run.mjs typecheck
node scripts/run.mjs test
node scripts/run.mjs ui-test
node scripts/run.mjs build
```

Установка: `node scripts/run.mjs install`. Загрузки npm и кэши Vitest направлены в проектную `.cache`. Запускатель скрывает дочерние процессы Windows, закрепляет threads и скрывает вспомогательную проверку сетевых дисков Vite.

Проверки включают 49 модульных тестов, 9 браузерных сценариев DnD, 5 групп сценариев палитр, 7 групп ручного пути и 5 групп сценариев AI-экрана и 3 группы сценариев настроек подключения. DnD через dnd-kit проверяется мышью, клавиатурой и touch, включая отмену, недоступную роль, автопрокрутку списка из 60 строк, независимость звезды и передачу порядка из Composer в создание композиции. Палитры проверяются через создание, использование при генерации, сохранение, повторное открытие, импорт/экспорт, ошибки и узкую панель. Путь создания дополнительно проверяет выбор, возвраты, импорт, повторную генерацию, ошибки и передачу управления Figma. Браузерные проверки запускают установленный Edge без окна через Playwright; временные файлы находятся в `.cache/playwright` и `.cache/qa`. Список из 60 строк проверяет устойчивость прокрутки, лимит генерации остаётся 8 предметов. Браузерные проверки сами по себе не подтверждают физический жест в Figma Desktop.

Сборка с DnD загружена в работающую Figma Desktop через автоматическое обновление плагина. Через agent-desktop открыты стартовый набор, композиция и панель «Слои»; доступны ручки переноса всех трёх выбранных предметов. Физический жест перетаскивания внутри Figma Desktop в этом проходе не выполнялся. Figma MCP и Codex Computer Use не использовались.

`scripts/prepare-assets.py` повторно собирает стартовую библиотеку из ранее выгруженных материалов SnapBuild по локальному пути; для обычной сборки запускать его не нужно, готовые данные входят в `src/assets`.

Визуальная проверка раскладки: `node scripts/preview-layout.mjs`, затем `node scripts/render-svg.mjs .cache/qa/layout-gallery.svg .cache/qa/layout-gallery.png 1160`. Требуются Python с Pillow и установленный Inkscape по пути `C:/Program Files/Inkscape/bin/inkscape.exe`. Галерея содержит девять сочетаний исходных предметов в трёх форматах, включая несколько фоновых версий, и использует анализ их растеризованных силуэтов. Временные SVG, PNG и профиль Inkscape находятся в проектной `.cache`.
