# AI-подключение

Настройки открываются иконкой в заголовке Mixer. Главный экран сохраняет библиотеку, палитру и промпт.

Рядом с базовым адресом, моделью и ключом есть кнопки «?». Они открывают небольшие пояснения по нажатию, наведению или фокусу с клавиатуры. Escape закрывает подсказку, оставляя настройки открытыми.

Справа от ID модели находится кнопка получения списка. Сначала введите ключ или используйте уже заданный ключ того же сервиса, затем нажмите кнопку. Mixer выполняет один стандартный `GET {baseUrl}/models` с Bearer-ключом. Заранее знать ID модели и сохранять подключение для этого не требуется. После успешного опроса в форме автоматически выбирается первая модель. Поле модели — один редактируемый селектор: нажатие раскрывает весь полученный список, ввод текста фильтрует его или задаёт свой ID. Отдельного поля поиска нет. Стрелки клавиатуры и Enter выбирают вариант, Escape закрывает список. После сохранения список остаётся доступным при повторном открытии настроек в текущем запуске плагина.

Опрос подставляет первую модель в форму, но не меняет действующее подключение до нажатия «Сохранить» и не запускает генерацию. При смене провайдера, адреса или ключа старый ответ отбрасывается. Если сервис не поддерживает стандартный список, ключ не имеет права на его чтение или запрос не завершился за 15 секунд, можно ввести ID вручную. Список может включать модели для разных задач; для Mixer нужно выбрать текстовую модель. Отдельных коннекторов для провайдеров нет.

| Провайдер | Базовый адрес по умолчанию | Начальная модель |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4.1-mini` |
| OpenAI-совместимый сервис | Задаётся пользователем | Задаётся пользователем |

Модель редактируется во всех режимах. Для своего адреса нужно выбрать совместимый сервис. Принимается базовый HTTP(S) URL или полный путь `/chat/completions`; последний нормализуется. URL с query-параметрами, фрагментом или встроенным логином отклоняется; ключ задаётся отдельным полем. Azure и другие API с отдельной схемой авторизации или обязательными query-параметрами не являются поддержанным форматом подключения.

Ключ не проверяется по префиксу: подходят в том числе проектные ключи OpenAI и ключи совместимых провайдеров. Он должен соответствовать сервису, иметь доступ к модели и быть записан одной строкой. Модель должна поддерживать текстовые Chat Completions и возвращать JSON по инструкции.

«Сохранить» сохраняет адрес, провайдер и модель в `figma.clientStorage` под ключом `mixer-ai-config-v1`. API-ключ остаётся только в памяти запущенного плагина, не попадает в документ, клиентское хранилище или сборку. При изменении модели внутри того же подключения ключ можно оставить прежним. При смене сервиса или адреса требуется его ключ. Загрузка key.txt из UI удалена.

Запросы отправляются только на выбранный адрес, без автоматического переключения на другого провайдера. Для произвольного адреса в манифесте разрешена сеть `*` с объяснением назначения. Проверка авторизации и доступности модели происходит при первой генерации, а не при сохранении настроек.

OpenAI получает `max_completion_tokens` и JSON mode; DeepSeek — `max_tokens`, JSON mode и отключённый thinking. Совместимый сервис получает базовые `model`, `messages`, `max_tokens`, без расширений DeepSeek и обязательного `response_format`. Ответ проверяется как JSON и затем проходит проверку предметов, палитр и ролей. Ошибки ключа, адреса, модели, пустого и не-JSON ответа показываются пользователю; автоматических повторных платных запросов нет.

Настройки используются и для основной генерации, и для дополнительного смыслового подбора предметов. Если генерация ожидала подключения, сохранение возобновляет исходный запрос после завершения операции настройки. Закрытие диалога отменяет это ожидание.

## Проверки и источники

Модульные и браузерные проверки покрывают payload OpenAI, DeepSeek и совместимого сервиса; произвольные ключи и ID моделей, смену сервиса без переноса ключа, изменение модели, восстановление публичных настроек и отсутствие загрузки файла.

Проверки списка моделей охватывают общий GET для трёх режимов, пустой ID, ключ текущего сервиса, поиск и выбор, запоздалый ответ после смены провайдера и ручной ввод при ошибке. Подсказки проверены с клавиатуры и в панели шириной 400 px. Через тот же адаптер выполнено одно реальное чтение списка DeepSeek в фоне: получены `deepseek-flash` и `deepseek-v4-pro`. Генерация не запускалась, Figma на передний план не выводилась. Артефакт — `.cache/qa/model-discovery-live.json`.

Дополнительно в фоне выполнена HTTP-проверка планировщика на локальном совместимом сервере: выбранные endpoint и модель, два валидных плана и два вызова границы рендера. Реальные ключи OpenAI и платные API при этой проверке не использовались. Управление Figma и проверка сети из её процесса в этом проходе не завершались после просьбы пользователя работать без фокуса. Артефакты находятся в локальной `.cache/qa/ai-settings-browser` и `.cache/qa/compatible-endpoint-result.json`.

Контракт сверён с [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [страницей GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) и [сетевыми разрешениями Figma](https://developers.figma.com/docs/plugins/manifest/).
